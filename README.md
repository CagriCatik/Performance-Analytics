# SaaS Pulse — Product Analytics Reference Dashboard

A self-contained reference project for **data modeling and dashboard design** using Power BI.  
The dataset is entirely synthetic — generated by Python — so no external data source, licence, or API key is needed. The focus is on the end-to-end pipeline: data model design, DAX measure library, Power Query transformation layer, and a production-quality 12-page Power BI report covering the full SaaS metrics surface.

---

## Purpose

This project is not about the data itself. It is about:

- **Semantic data modeling** — star schema with conformed dimensions, slowly changing attributes, and a clean fact/dimension separation
- **DAX measure design** — 55+ measures covering revenue (MRR/ARR), churn, engagement, support, and period-over-period comparisons, all centralised in a single measure table
- **Power Query layer** — parameterised M queries with a shared file-path helper, typed columns, and locale-aware date handling
- **Dashboard composition** — 12 report pages using the full range of native Power BI visuals: line, bar, column, combo, area, waterfall, ribbon, funnel, scatter, treemap, donut, filled map, gauge, KPI card, matrix, pivot table, multi-row card, and anomaly-detection charts
- **Synthetic data generation** — reproducible Python generators that produce realistic distributions, risk-weighted relationships, and intentional data-quality issues to stress-test the model

## Data model

The semantic model follows a **star schema** with one measure table and no vehicle, fleet, or industry-specific assumptions — it is intentionally domain-generic so the modeling patterns transfer to other contexts.

| Layer | Tables |
| --- | --- |
| Fact | FactMonthlyMetrics, FactSubscriptionEvents, FactSupportTickets, FactRefunds, FactLiveActivity |
| Dimension | DimDate, DimAccount, DimSubscription, DimPlan, DimRegion, DimSegmentBand |
| Measures | KPI_Measures (55+ DAX measures) |

### What the synthetic data represents

The generators simulate a B2B SaaS business with ~400 customer accounts, ~600 subscriptions across four plan tiers, 12 months of monthly operational metrics, subscription lifecycle events, support tickets, and billing refunds. A live-session feed is also simulated via a local HTTP server.

| Entity | Rows (approx.) | Description |
| --- | --- | --- |
| Accounts | 400 | Companies across segments (SMB / Mid-Market / Enterprise) and industries |
| Subscriptions | 600 | One or more per account, linked to a plan and billing cycle |
| Monthly Metrics | 6 000+ | MRR, active users, API calls, feature adoption %, NPS per subscription per month |
| Subscription Events | 1 800 | Upgrades, downgrades, renewals, churns, reactivations |
| Support Tickets | 2 400 | Tickets by category and severity with resolution time and FCR flag |
| Refunds | 300 | Billing refunds linked to tickets |
| Live Activity | 600 | Point-in-time user session snapshot, refreshable via local server |

Risk factors are seeded per subscription so that higher-risk accounts receive disproportionately more tickets, lower feature adoption, and more churn/downgrade events — this creates the correlations that make driver analysis meaningful.

## Quick start

```bash
# 1. Install Python dependencies
pip install -r requirements.txt

# 2. Generate the synthetic dataset
python -m src.synthetic_data.generator --config config/generator.yaml

# 3. Build the Power BI project (TMDL + Power Query + report pages)
python scripts/build_powerbi_project.py

# 4. Open in Power BI Desktop
#    File → Open → powerbi/SaasPulse.pbip
#
#    Required one-time setting to load local CSV files:
#    File → Options and Settings → Options → Current File → Privacy
#    → Ignore the Privacy Levels and potentially improve performance

# 5. Optional: start the live activity server
python -m src.synthetic_data.server
# Then refresh the Live Activity Dashboard page in Power BI
```

### Run tests

```bash
pytest -q
# 15 tests: generation, referential integrity, domain invariants, Power BI project structure
```

## Design decisions

**Why synthetic data?**  
Real SaaS data carries PII and business sensitivity. Synthetic data with seeded risk factors and realistic distributions gives full control over data quality scenarios without any of the compliance overhead.

**Why PBIP / TMDL instead of .pbix?**  
PBIP format stores the semantic model and report as human-readable text files (TMDL + JSON). This makes the entire Power BI artefact version-controllable, diff-able, and buildable from code — `build_powerbi_project.py` generates every table, measure, relationship, and report page programmatically.

**Why a separate measure table?**  
All 55+ DAX measures live in `KPI_Measures`, a calculated table with no rows. This keeps the field list clean, makes measures easy to find regardless of which fact table they query, and mirrors how enterprise Power BI models are typically structured.
